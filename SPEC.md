# Codex Orchestrator Behavioral Specification (`v4.0.0`)

This document defines the stable **Session / Hands** behavioral invariants and conformance contract for `codex-orchestrator`. Orchestration policies and prompts live in the disposable **Brain** layer (`rules/`, `skills/`).

## 1. Architecture Boundaries (Brain / Session / Hands)

* **Brain (`rules/`, `skills/`, `workflows/`)**: Lean (`<= 30` lines) always-on Fold-First ladder, 1-hop priority, Spec templates, `/swarm` & `/run-workflow` composition guides, and Communication Charter (`v3.2`).
* **Session (Immutable Artifacts & `SPEC.md`)**: Numbered append-only attempt history under `<out-dir>/attempts/attempt-NNN/` with atomic top-level latest publication (`summary.json` written last), plus `changes.patch`, `verification.json`, and `parallel-summary.json`. `resume` discovery ignores `attempts/*/` duplicates.
* **Hands (`scripts/codex_orch/`, `config/profiles.json`, thin `.sh` shims)**: Zero-dependency Python 3 stdlib execution kernel invoked via `exec python3 -I -B` (immune to CWD shadowing and Bash offset self-edit crashes), separating shared core logic from thin host adapters (`host_adapter.py`).

For `resume --id`, discovery checks the run root (`RUNS_DIR`) and directories up to eight levels below it. An explicit `--out-dir` also supplies a direct summary candidate and enables a three-level search under its parent when the parent is outside `RUNS_DIR` and is neither the filesystem root, a system temp directory, nor the home directory. Discovery prunes symlinks and attempt, worktree, Git, Python cache, and Node dependency directories. The newest matching top-level summary supplies the prior model and eligible writable directories.

Resume summaries record `resume_bloat_warning` and any `resume_bloat_reasons`, plus `prior_session` metadata when a match is available. The prior summary link uses the immutable attempt summary when available, including when `resume` reuses `--out-dir`. A prior run with at least 1,000,000 input tokens or status `timeout` or `stall_timeout` emits an advisory warning without changing the exit code.

## 2. Fail-Closed Exit Code & Status Contract

Wrapper status is strictly separated from child `codex_exit_code`:

| Wrapper `status` | Wrapper `exit_code` | Condition |
| :--- | ---: | :--- |
| `ok` | `0` | Child exited `0`, no cancellation/timeout/quota failure, requested schema valid, path policies clean, custody verified, and host verification (if requested) passed. |
| Usage / Preflight error | `2` | Invalid CLI args, unreadable/unsupported `--schema` keyword, invalid trusted `.codex-orchestrator.json` (e.g. forbidden `before_run` hook), unreadable explicit config/rules, bidirectional self-hosting guard hit, or `--dirty-policy fail` on dirty checkout. **Must exit before creating `--out-dir`.** |
| `schema_error` | `3` | Child exited `0` but `last_message.md` failed JSON or JSON Schema validation when `--structured`/`--schema` was requested. |
| `tdd_red_failed` | `4` | Opt-in `--tdd` Stage RED did not produce a genuine collected assertion failure (rejects `Ran 0 tests`, `collected 0 items`, `ImportError`, `ModuleNotFoundError`, `SyntaxError`, `ERROR collecting`, or exit `0`). |
| `protected_path_violation` / `scope_violation` | `5` | Worker added, modified, deleted, or renamed a file matching `protected_paths` (including frozen TDD tests) or outside non-empty `allowed_paths`. Worktree is preserved. |
| `verification_failed` | `6` | Host-side Proof-of-Work (`--verify-cmd`/`--verify-preset`) or TDD Stage GREEN failed (non-zero exit, tree mismatch, 0 collected tests, or unexpected skips without `--tdd-allow-skips`). |
| `ls_api_unreachable` | `7` | `handoff.sh create` could not reach Antigravity `product.v1.ConversationService` (missing LS env, connection refused/timeout, or HTTP 403 sandbox block). Validated packet, manifest, and fallback prompt remain intact on disk. |
| `paused_quota` | child code or `75` | Child exited **non-zero** with unambiguous quota/rate-limit signals in `stderr` or JSONL `error`/`turn.failed` events (never triggered when `codex_exit_code == 0` or by normal command/prose output). |
| `timeout` | `124` | Hard monotonic wall timeout (`--timeout`) expired and triggered process-tree cleanup. |
| `stall_timeout` | `125` | Opt-in monotonic event inactivity timeout (`--stall-timeout`) expired and triggered process-tree cleanup. |
| `cancelled` | `128 + signal` | Wrapper/supervisor received `SIGTERM`/`SIGINT`, triggered process-tree cleanup, and failed closed even if the child exited `0`. |
| `error` | child exit code / `1` | Child exited non-zero, custody check failed, or fresh matching `summary.json` / `invocation_id` missing. |

The Codex supervisor and host verification snapshot descendant PIDs and PGIDs before signaling the root group, including tools that started separate process groups. Cleanup tracks new descendants during the grace period and verifies each tracked PID's start time before using it to target `SIGKILL`. A finished root process with a surviving root group still triggers cleanup. The supervisor also samples descendants every 0.5 seconds while the root is running. On POSIX systems such as macOS, without OS subreapers or cgroups, a descendant that detaches into a separate PGID and outlives a parent that exits before the first sample can escape cleanup.

## 3. Declarative Profiles (`config/profiles.json`)

Model, effort, speed, verbosity, stdout, command budgets, and bundled schema mappings are declared in `skills/codex-orchestrator/config/profiles.json` (override with `--profiles-file` or `CODEX_ORCH_PROFILES_FILE`). `consult` and `implement` default to `gpt-6.2-sol`. The other modes default to `gpt-6.2-astra`, subject to prior model inheritance on resume.

* `verbosity_by_mode` selects `low` for `implement` and `medium` for other modes. Use `--verbosity low|medium|high|inherit` to override it. An explicit Codex `--profile` defaults to `inherit`. Unsupported models warn and fall back to `inherit`. User `-c model_verbosity=...` is applied after the routed setting. Older profile files without the new routing keys continue to load with inherited verbosity and automatic stdout.
* Exec prompts append `OUTPUT_CLARITY_FOOTER` after the other prompt conditioning. Use `--no-clarity-footer` to opt out. Native review has no injected prompt. Single and parallel runners accept both controls, including per-task manifest overrides in parallel. The worker summary records resolved `verbosity` and the `clarity_footer` setting.
* `review --structured` selects the strict `review-output-schema.json` in read-only exec. The receipt records verdict, findings with P0–P3 severity, verification, and unverified areas. All five bundled schemas describe how to supply complete sentences, exact anchors, and explicit gaps.

## 4. Private-Index Patch Custody & Ownership Table (`parallel_runner.py`)

1. Resolve `base_oid` (`git rev-parse --verify HEAD`) per selected checkout root (`git_root`).
2. Reject unmerged index entries (`git ls-files -u`). Snapshot final Git-visible tree via racy-git-safe private `GIT_INDEX_FILE` (`copy real index -> add -A -> write-tree -> unlink -> read-tree staged_tree -> add -A -> write-tree`) capturing commits, force-staged ignored files, unstaged edits, deletions, and new non-ignored files while ignoring ordinary `.gitignore` caches.
3. Derive `changes.patch` and `changed_files` from the exact `(base_oid, final_tree_oid)` pair and verify independent reconstruction (`reconstructed_tree_oid == final_tree_oid`) before removing any worktree. Never fall back to `shutil.rmtree` on Git cleanup failure.
4. Run merge checks in atomic private temp dirs, reporting `base_reconstruct_ok` separately from `target_apply_ok`.
5. For multi-task `/dag` runs, auto-inject a public **Parallel Ownership Table** into per-task `effective_spec.md` (without mutating caller specs) and enforce `allowed_paths`/`protected_paths` fail-closed.

## 5. Trusted Repo Contract, Proof-of-Work & Opt-In Independent TDD (`verify.py`)

* **Trusted Policy Provenance**: Optional `.codex-orchestrator.json` is loaded strictly from `git show <base_oid>:.codex-orchestrator.json` or explicit `--contract <FILE>` — NEVER from the Codex-modified candidate tree. Only declarative keys (`version`, `allowed_paths`, `protected_paths`, `dirty_policy`, `max_timeout_s`, `verify_commands` as argv lists) are permitted; arbitrary shell hooks (`before_run`, `after_run`) are rejected at preflight.
* **Host-Side Proof-of-Work (`verification.json`)**: Runs `verify_argv` with `shell=False` and `build_child_env()` (credentials stripped, `GIT_CEILING_DIRECTORIES` scoped) inside a clean detached verify worktree reconstructed from `base_oid` + verified patches, recording `(base_oid, test_snapshot_tree, candidate_tree_oid, reconstructed_tree_oid, argv, cwd_rel, policy_source, exit_code, redacted tails)`. *Trust boundary*: verification executes under the local OS user account rather than a kernel/VM sandbox; run inside an OS/container sandbox when evaluating untrusted third-party repositories.
* **Opt-In Cross-Model TDD (`--tdd`)**: Two-snapshot protocol (`base_oid -> test_snapshot_commit`, requiring a non-empty frozen test set via `--tdd-test-dir` or `--tdd-test-path`): verify true RED before launching Codex -> run Codex relative to `test_snapshot_commit` with exact-path + glob `protected_paths` enforcement -> verify true GREEN requiring positive collected test execution count (`collected > 0`) and zero unexpected skips (unless `--tdd-allow-skips`).

## 6. Security, Stdout Hygiene & Native Composition

* **Credential Isolation**: `codex_orch.env.build_child_env` strips host SSH/cloud/platform tokens while preserving Codex auth and runtime essentials; `ensure_private_dir` rejects symlinks and verifies POSIX owner + `0700` mode; secrets are redacted from diagnostics.
* **Bounded Stdout (`--stdout-mode auto|compact|facts|full`)**: `stdout_mode_by_mode` selects `facts` for `implement` and `auto` otherwise. Parallel workers resolve their own defaults when no override is supplied. `auto` compacts responses larger than 4096 bytes. `facts` previews expose verdict tokens, collection counts, severity and check rollups, and file pointers within the UTF-8 byte budget. Non-JSON responses yield only a format marker and file pointers.
* **Objective host evidence and commentary quarantine**: The wrapper prints the changed-file count, a bounded path list, patch path and size, and host verification status and artifact path before the last-message preview when those artifacts exist. `partial_progress.last_agent_messages` remains in the failure `summary.json` on disk and is omitted from stdout in every mode. In `facts` mode, raw failure diagnostics remain available through the event and stderr artifacts.
* **Communication Charter v3.2**: Inspect `git diff --stat`, key hunks and host `verification.json` against every Spec acceptance item before consulting implementation prose. Flag missing proof and spot-check cited anchors for read-only work. The Synthesis Firewall preserves hard evidence and turns internal working language into self-contained Chinese.
* **Loose Antigravity Composition**: Use native `/swarm` (`land-before-kill`) + `/review` for interactive collaborative coding with external Codex final audit; use reusable read-only `/run-workflow` templates (`workflows/research_parallel.py`, `workflows/debate_multi_critic.py`) for card-based multi-slice research/critique.

## 7. Context Telemetry, Native Handoff Hook & Session Handoff (`context_telemetry.py`, `context_hook.py`, `handoff.py`)

* **Dual-Constraint Performance Thresholds**: `config/profiles.json` (`context_handoff`) defines Antigravity platform truncation limits (`cpLimit`) per model family (Gemini 4 / Orchestrator `512,000`, Claude 5.5 / Gemini 3.8 `256,000`, Claude 4.6 `160,000`, Gemini 3.1 Pro `128,000`, GPT-OSS `80,000`; Orchestrator dual-model sessions take the conservative minimum). Active usage is `input_tokens + cache_read_tokens` from the latest `PLANNER_RESPONSE` after the last `CHECKPOINT`. Default watermarks are `Soft = min(200K, 45% × cpLimit)`, `Hard = min(300K, 65% × cpLimit)`, and `Emergency = 80% × cpLimit`, overridable via `CODEX_HANDOFF_*` env vars.
* **Native Lifecycle Hook (`codex-context-handoff`)**: Fail-open `PreInvocation` + `Stop` hook (`scripts/hook_context_guard.py`, `timeout: 5s`) shares per-conversation state and `fcntl.flock` locking with `handoff.sh` (`$PLUGIN_DATA/handoff_state` -> `$ANTIGRAVITY_APP_DATA_DIR/plugin_data/codex-orchestrator/handoff_state` -> `/tmp/codex-orchestrator/handoff-state`), filters child subagents (offline transcript step-0 bootstrap or hook payload, with `GetConversation` metadata fallback, cached per conversation), resets watermark bands on `/compact` (`checkpoint_epoch`), fires each band at most once per epoch, flags checkpoint fatigue (`checkpoint_count >= 2`), emits a single anti-split-brain reminder if an already handed-off session keeps invoking tools in the same turn, and triggers a single `Stop` `decision: "continue"` nudge **only** when the effective handoff mode is `auto` when `terminationReason == "NO_TOOL_CALL"`, `fullyIdle == true`, `continuationActive == false`, `band in ("hard", "emergency")`, `handed_off == false`, and `hop_index < max_hops`. By default, `PreInvocation` embeds `[codex-context-handoff:<band>]` and the concise Chinese token status directly in `systemMessage` without a `metadata` map (avoiding Antigravity `v2.35.1`'s `ScrubInternalFields` Go panic on non-empty `map<string, string>` metadata); set `CODEX_HANDOFF_HOOK_METADATA=1` to opt into `metadata.user_markdown` once the host fix ships.
* **Lossless Session Handoff (`scripts/handoff.sh`)**: Thin `exec python3 -I -B` shim supporting `inspect`, `validate`, and `create`. Preflight fails closed (exit `2`) on missing sections (`## 1.`–`## 8.`), unresolved `<!-- ... -->` placeholders, size outside `400 B – 24 KB`, missing referenced paths in Sections 6–7 (ignoring single-segment slash commands such as `/handoff` and `/impl`), unredacted secrets or `ANTIGRAVITY_CSRF_TOKEN`, Git unmerged/conflict markers, non-root child conversations (without `--allow-child`), `next_hop > max_hops`, or duplicate handoff within the same `(conversationId, checkpoint_epoch)` (without `--force`). Appends deterministic `## 9. Deterministic Runtime Snapshot` (including read-only local `dispatch_runs` summaries auto-discovered from `$PLUGIN_DATA/dispatch_runs.json` or explicit `--dispatch-run-dir` with zero SSH), persists canonical artifacts under `<ANTIGRAVITY_APP_DATA_DIR>/brain/<cid>/handoff/` + `/tmp/codex-orchestrator/handoffs/<chain>/latest.json`, calls `product.v1.ConversationService` (`GetConversation` -> `CreateConversation` preserving `projectId`, `environmentId`, and exact model with 4xx tier fallback -> `UpdateConversation` preserving `conversationGroupId` and tagging old conversation `handoff-completed`, archiving only when `--archive-old` or `CODEX_HANDOFF_ARCHIVE_OLD=1`), and never logs or persists `ANTIGRAVITY_CSRF_TOKEN`.

* **Remote Runner** handles remote SSH, sync, cluster operations, and Launch-Verify-Return with `run_command`, `read_file`, and `manage_task`. Its contract bars local source edits, handoff, and sandbox bypass. It returns a compact receipt after one atomic wave.
* **Tool activity** shares the single transcript pass used for token telemetry. Decode JSON-quoted string args as well as plain strings. Count remote commands by shell command position after assignments and supported wrappers, including `kubectl exec` and `docker exec` after global options. Exclude orchestrator helper invocations. Count task status calls and reads outside handoff and Codex temp artifacts. Planner rows without tools preserve the remote streak. Non-remote tool turns break it. A `CHECKPOINT` resets remote calls, the streak, read count, and recorded subagent invocations.
* **Read guard (`codex-read-guard`)** runs at `PreToolUse`. By default, it denies unbounded or oversized main-loop text reads of local files larger than 20 KiB. A bounded range of up to 450 lines is allowed. The denial directs callers to a tighter range, `rg` or `python3` extraction, or built-in `research`. Child subagent reads, handoff packet reads, and explicit user requests to read the full file are exempt. Set `CODEX_READ_GUARD=off` to disable the guard.
* **Errored read telemetry** matches `GENERIC` tool results to planner calls by step index, with sequential matching when an index is missing. An `ERROR` result excludes its `read_file` call from all read metrics, duplicate-path tracking, and the previous-turn read flag. Unmatched calls still count, including in planner-only transcripts. Counters follow planner call order, `research` resets the reads-since-research counter, and a checkpoint discards pending calls and resets the counters.
* **Horizontal noise nudges** use `context_handoff.noise_nudge` and the `CODEX_NOISE_NUDGE` override. The default remote nudge suggests `remote-runner` after four remote calls or three consecutive remote tool turns and skips conversations that already invoked it during the epoch. Without a `research` invocation in the epoch, `read_noise` suggests `research` and bounded reads at six counted reads and `min(45,000, 12% × cpLimit)` active tokens, or when a counted read in the previous turn accompanies a token gain of at least 25,000. `read_noise_l2` urges `research` delegation or targeted extraction after six additional counted reads following the first nudge without a research invocation, or after twelve reads since the latest `research` invocation at the same active-token floor. Each nudge fires once per checkpoint epoch. `PreInvocation` injects at most one message, prioritizing the post-handoff guard, vertical watermark or fatigue, remote noise, then read noise. Notices skip child subagents. Noise nudges remain available with `CODEX_HANDOFF_MODE=off` and omit `systemMessage.metadata` by default.
* **Chain auto-handoff** resolves mode from a valid explicit `CODEX_HANDOFF_MODE`, then inherited `handoff-mode:auto|propose`, then the profile default (`propose` in the bundled profile). `create --resume-mode auto` tags and pre-seeds the successor, including on timeout reconciliation. The bootstrap launches any optional parallel subagent track in Packet Section 2 on the first turn. At `hop_index >= max_hops`, `PreInvocation` watermark and checkpoint fatigue notices suggest `/compact`. `inspect` exposes `effective_mode` and `tool_activity`, and resolves child status from the transcript step-0 bootstrap when uncached, with a read-only `GetConversation` fallback for safe conversation IDs when Language Server credentials are available.

## 8. Remote Multi-Server GPU Master Scheduler (remote_dispatch.sh)

* **Control plane.** `scripts/remote_dispatch.sh` enters the standard-library-only `codex_orch/remote/*` controller. The local hub owns run state and GPU placement. SSH spokes probe hosts and launch detached remote attempts. Keep real cluster inventory, personal paths, and server IPs outside the plugin repository.
* **Preflight.** A fresh start validates the strict inventory and manifest schemas, DAG, and host placeholders before creating `--run-dir`. Invalid configuration exits `2`. An initial start exits `6` when zero hosts pass preflight and the initial probe and the run is still nonterminal with no task progress.
* **SSH transport.** ControlMaster multiplexing uses `/tmp/co-ssh-<uid>/%C` with a `0700` socket directory and an expanded path shorter than the 104-byte `sun_path` limit. The transport invokes SSH with `shell=False`, accepts inventory SSH options from a safe allowlist, and limits calls with a per-host `max_ssh_concurrency` semaphore.
* **Placement, gang reservation, and DAG isolation.** Deterministic work-stealing ranks ready tasks by priority, downstream dependency impact as a critical-path heuristic, GPU count, and longest processing time (LPT), with stable tie-breakers. Placement prefers locality among eligible hosts subject to affinity and resource constraints. Multi-GPU (`gpus > 1`) tasks reserve and drain the fastest eligible host (`draining_for`) so lower-priority 1-GPU tasks cannot starve them while other hosts continue 1-GPU sweeps; reservations release automatically if the task leaves `ready` or host usable GPUs drop below `gpus`. `add-tasks` injects validated tasks into active runs under `dispatch.lock` + `state.lock`. An upstream failure marks only tasks that depend on it through explicit DAG edges as `blocked_dep`. With `allow_partial_deps`, a task may proceed when all dependencies are terminal and at least one completed.
* **Co-tenancy, watchdogs, and recovery.** Single-RPC probes handle PID-namespaced containers (e.g., DSW/Docker) by counting managed `/dev/nvidia<idx>` holders on leased GPUs so scheduler-owned processes do not trigger false external collisions while unleased GPUs and excess foreign processes remain detected across `skip_gpu`, `preempt_gpu`, `yield_host`, and `ignore`. Probes also support cross-host `done_markers` pre-checks to skip already-completed tasks before dispatch, and capture `task.log` size/mtime + GPU utilization for clock-skew-safe `stall_timeout_s` watchdog termination. Non-retryable exit codes and log patterns record exact failure reasons even with `max_retries=0`. The default `retry_on_host_lost=false` avoids duplicate execution during an outage, `stop --kill-remote` transitions confirmed killed attempts to `cancelled`, and the controller adopts surviving attempts on reconnect.
* **Artifacts, cross-host relay, and handoff.** SSH streams `tar` for sync and lightweight result retrieval with zero `rsync` dependency. Hosts may mirror results to `mirror_root`, and local extraction rejects unsafe archive entries. Declared `relay_inputs` stream artifacts `Source -> Hub -> Target` outside `state.lock` (task state `relaying`) with target cache hits, byte-offset resume, prefix/full SHA256 verification, and `max_bytes` hard caps, updating `{dep.<id>.out_dir}` and optional `{inputs_dir}` transparently. Active runs register in `$PLUGIN_DATA/dispatch_runs.json` for automatic `/handoff` Section 9 snapshots; detached controllers never block the Quiescence Gate.
